# 汇报演示脚本(总时长约 5 分钟)

## 演示前检查清单
- [ ] 两个终端都已激活虚拟环境:uvicorn(API)和 streamlit(界面)都在运行
- [ ] 提前完整跑一遍三个场景,确认网络和 API 余额正常
- [ ] 备份:每个场景录屏或截图。现场网络或接口出问题时直接放录屏
- [ ] 浏览器放大到投屏可读;关闭无关通知

## 场景 1:雷达通信丢失(约 2 分钟)
- 操作:选案例 1 → 开始分析
- 讲:"测试员只记了一个时间:ACC 突然降级。系统自动圈出前后 12 秒窗口,
  把近千行日志压缩成一条证据链:雷达链路丢失 → DTC 置位 → ACC/AEB 降级。"
- 指给领导看:证据链表格里每条都带时间戳和原始消息;报告里每个论断都标了证据时间和知识库来源
- 强调:**结论和置信度由规则和数据算出来,AI 只负责把它写成人话**

## 场景 2:驾驶员取消 ACC(约 1.5 分钟)
- 操作:选案例 4 → 开始分析 → 流程暂停 → 点"是,确认为人为操作"
- 讲:"系统发现这是驾驶员按键导致的退出,但它不会自己下结论。
  和我们现在的排查流程一致:先看视频确认是不是人为,这一步留给人。"
- 强调:**高风险判断必须有人确认**

## 场景 3:证据不足(约 1 分钟)
- 操作:选案例 5 → 开始分析
- 讲:"日志里没有任何已知的故障模式。系统没有编原因,而是明确说证据不足,
  并把唯一的陌生消息列出来交给工程师。"
- 强调:**它会说"我不确定"**

## 可能的追问与回答
| 问题 | 回答要点 |
|---|---|
| 准确率多少? | 目前只用模拟数据验证了流程和安全机制,没有真实准确率,不报数字。试点阶段用若干历史案例度量"根因命中率"和"定位时间缩短" |
| 会不会胡说? | 结论由规则和数据产生;报告强制引用证据时间;无关问题拒答;证据不足明说;高风险环节人工确认;有自动化测试覆盖这些行为 |
| 数据安全? | 演示用的是模拟数据。落地时部署在内网,使用公司批准的模型端点(代码已支持只改配置就切换),原始日志不出内网 |
| 为什么不直接用通用的聊天 AI? | 日志不能发给外部;通用模型不懂我们的故障码矩阵和日志格式;它给不出可追溯的证据链 |
| 会不会替代工程师? | 不替代。它减少翻日志的重复劳动,判断仍由工程师做,关键节点有人工确认 |
| 要多少资源、多久? | 试点周期和人力需要和 FO 对齐后再报(此处先留空,不要随口承诺)。需要的支持:矩阵导入批准、知识库编写、日志访问权限、平台对接人 |
| 和现有 MCAP 查看工具的关系? | 互补。助手负责告诉你"该看哪里",深入分析仍用现有工具。后续可以接入信号层数据提升准确度 |
